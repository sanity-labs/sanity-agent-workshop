# Checkpoint 2-1 · Run code when content changes

_Correct if you're still on the Green & Gather seed._

**Local run.** `sanity functions test draft-menu-copy --dataset production --with-user-token
--document-id gg.menuItem.harissa-chickpea-bowl` prints:

```
✔ Function execution succeeded.
[draft-menu-copy] menuItem gg.menuItem.harissa-chickpea-bowl "Harissa Chickpea Bowl" → recipe: gg.recipe.harissa-chickpea-bowl  (local run — nothing is written)
```

**The explanation you should hear.** The blueprint fires on `menuItem` create and update; the
filter `_type == "menuItem" && !defined(description.base)` limits it to items with no drafted
copy yet — which is every seeded item — and is the recursion guard for when the Function starts
writing that field; the projection `{_id, _type, title, recipe}` shapes `event.data`, so anything
else (ingredients, the cross-contact statement) is a query inside the handler.

**In the Studio.** Start `npx sanity functions logs draft-menu-copy --watch` in a spare terminal
first (it reports "No logs found" on a fresh project — a clean baseline). Then open a menu item,
change anything, publish. Within a few seconds the watcher prints `Function invocation started`
and the same log line for that item, without the "(local run)" tail. Creating a new menu item and
publishing it does the same (and, once Mission 2-4 is done, starts a workflow).

**What does not show it:** the emulator on port 8080. It is a payload editor — pick the function,
type a document id, run — not an event subscriber. A Studio publish fires the _deployed_ Function,
which bootstrap deployed. `sanity functions test` also evaluates the blueprint filter before
invoking: feed it a recipe document and it prints `Filter ... returned an empty result. Skipping
invoke.` — the fastest way to check a filter change without deploying.

**Nothing changed in the dataset.** This mission is log-only; the log line is the artifact.

**If "no such function"**, it isn't built — `pnpm --filter @starter/functions build`.

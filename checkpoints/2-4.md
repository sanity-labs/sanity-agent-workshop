# Checkpoint 2-4 · Put a human in front of it

_Correct on any project — this mission doesn't depend on the seed._

**Files.** `studio/workflows/menu-item-review.ts` exports a `defineWorkflow` named
`menu-item-review` with stages `drafting`, `review`, `approved`, a required `subject` field with
`initialValue: {type: 'input'}`, and a guard on `review` matching the subject with
`actions: ['publish']`. `studio/sanity.workflow.ts` exports a `defineWorkflowConfig` with
`name: 'production'`, `tag: 'production'`, `expectedMinReaderModel: 4`, and `workflowResource`
id `<yourProjectId>.production`. `sanity.config.ts` is unchanged. No schema changes.

**Deploy.** `--check` passed offline. `--dry-run` printed a diff of the definition. The real
deploy printed:

```
✔ Processed 1 definition(s) · production (production) → <projectId>.production
  ✔ created   menu-item-review v1
```

**In the Studio.** Create a **new** menu item (fresh — `autoStart` doesn't apply to existing
documents). The workflow strip above the form shows **Drafting** with no Start button needed. The
**Workflows** view beside the editor lists _Draft the description and allergen callout_; firing
_Submit for food-safety review_ moves the strip to **Food-safety review**. Now the document's
**Publish** action is **disabled**, with a tooltip naming the workflow. That is the hold. Firing
_Approve_ moves the strip to **Approved**, and Publish is enabled again.

**The history.** In the Workflows tool (navbar) → Overview → your run → the detail panel: the
start, the submit action, the transition to review, the approve action, the transition to approved,
each with who and when.

**The honest demonstration.** With another new item held at review, publish it from a terminal
with a write token (any client or `sanity documents create` against the published id). It lands:
the Content Lake doesn't evaluate guard documents during early access. And the instance is still
at `review`: it watches its own fields, and nothing wrote to them. Expected, not a bug — the
engine and the plugin honor the guard; the lake doesn't yet.

**If the Workflows view is empty**, the deploy tag doesn't match the plugin's tag, the definition
went to a different dataset, or its name isn't `menu-item-review` — check in that order. **If the
strip offers "Start workflow"** instead of auto-starting, the document already existed. **If the
strip shows the workflow greyed out**, the reason is in the browser console under
`[workflow-studio-plugin]`.
